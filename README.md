# Экопомощник

Учебное локальное приложение: ASP.NET Core Web API, SQLite/EF Core и статический frontend на HTML, CSS и JavaScript. Сценарии «Куда сдать», «Сообщить о нарушении» и AI-помощник подключены к backend. Gemini анализирует запрос; фактические ответы формируются сервером из SQLite.

## Запуск

Требуется .NET SDK 9. Проект использует .NET 9 и EF Core 9.0.16.

```powershell
dotnet restore
dotnet run
```

Откройте http://localhost:5080. ASP.NET раздаёт статические файлы из `wwwroot`; отдельный frontend-сервер и Node.js для запуска приложения не нужны. Четыре страницы: `index.html`, `recycling.html`, `violations.html`, `assistant.html`. Макет, цвета и типографика перенесены из `design-reference`; шрифты хранятся локально.

При первом запуске `SeedData.InitializeAsync` применяет миграции, создаёт `App_Data/ecohelper.db` и заполняет базу. Готовый SQLite-файл не требуется в репозитории. Следующие запуски сохраняют существующие данные и не добавляют копии демонстрационных записей. Начальное заполнение выполняется одной транзакцией. `App_Data`, SQLite-файлы и результаты сборки исключены из Git.

Для другой базы можно переопределить `ConnectionStrings__DefaultConnection`, например:

```powershell
$env:ConnectionStrings__DefaultConnection = 'Data Source=App_Data/another-demo.db;Foreign Keys=True'
dotnet run
```

Относительный путь базы разрешается от корня приложения. Новая база также создаётся и заполняется автоматически. Обычные формы работают без LLM. Для чата сервер читает `Gemini:ApiKey` из конфигурации ASP.NET Core (при локальном запуске Development — из User Secrets). Значение ключа не хранится в файлах проекта и не передаётся браузеру. Без ключа остальные страницы работают, а чат возвращает понятную ошибку HTTP 503.

Используется `gemini-3.5-flash-lite`. Первоначально запрошенная `gemini-2.5-flash-lite` вернула HTTP 404 как недоступная для новых проектов; замена согласована с пользователем. Подробности интеграции и проверки — в `docs/ai-verification.md`.

## Что находится в проекте

- `Controllers` — HTTP endpoints и проверка запросов.
- `Services` — поиск пунктов, подбор рекомендаций, анализ intent через `ILlmIntentService`/`GeminiIntentService` и формирование ответов `ChatService`.
- `DTO` — контракты API и ограничения входных параметров.
- `Models` — сущности базы и связи.
- `Data` — `AppDbContext` и `SeedData`.
- `Migrations` — версия схемы SQLite; эти файлы должны храниться в Git.
- `Utilities` — нормализация текста, в том числе кириллицы и `ё`/`е`.
- `wwwroot` — четыре HTML-страницы, общие CSS и JavaScript-модули.
- `wwwroot/js/api.js` — запросы к API, ошибки и таймаут.
- `wwwroot/js/storage.js` — черновики форм в `sessionStorage`.
- `wwwroot/js/recycling.js`, `violations.js` — шаги форм и вывод ответов сервера.
- `wwwroot/js/assistant.js` — текущий диалог, отправка сообщений, ответы и переходы с параметрами.
- `wwwroot/assets/fonts` — локальные Manrope, Playfair Display, DM Mono и лицензии.
- `docs/api.md` — параметры, ответы и ограничения API.
- `docs/regression-cases.json` — сохранённый пример ошибки классификации Figma для будущего отчёта.
- `scripts/Test-Api.ps1` — воспроизводимые проверки запущенного приложения.
- `scripts/test-ui.mjs` — браузерные проверки интерфейса через Playwright.
- `docs/frontend-verification.md` — результат проверки перенесённого интерфейса.
- `docs/ai-verification.md` — реальные результаты Gemini и проблемы интеграции.
- `scripts/test-chat.mjs` — реальные API/браузерные проверки чата (выполняют платные или квотируемые вызовы Gemini).
- `tests/EcoHelper.Checks` — автономные проверки JSON, ошибок и маршрутизации без внешнего AI.

## Демонстрационная база

Начальные данные: 6 категорий (стекло, батарейки, одежда, пластиковые крышки, бумага, электроника), их синонимы, 7 учебных пунктов, 4 типа нарушений и 24 записи организаций для этих типов. Регионы: Москва, Санкт-Петербург, Ленинградская область. В области есть учебные примеры для Всеволожска, Кудрово и Гатчины. Новые региональные записи добавляются однократно также в ранее созданную базу.

**Пункты, адреса и часы работы намеренно обозначены как учебные. Они не представляют реальные места приёма.** Для них нет вымышленных сайтов или расстояний. Каждый ответ сценария содержит `isDemoData: true`. Инструкции и рекомендации берутся из SQLite, а не генерируются моделью.

Организации используют существующие официальные ресурсы: [Департамент природопользования Москвы](https://www.mos.ru/eco/) и [Росприроднадзор](https://rpn.gov.ru/petition/). Общий ресурс не означает, что организация уполномочена рассмотреть любую ситуацию: перед обращением нужно уточнить компетенцию на её сайте. Сервис не отправляет обращения. [Росприроднадзор описывает порядок работы с обращениями](https://rpn.gov.ru/open-service/reception-of-citizens/order/).

## Проверка

После запуска приложения, во втором терминале:

```powershell
dotnet build --no-restore
powershell -ExecutionPolicy Bypass -File scripts/Test-Api.ps1
```

Можно передать `-BaseUrl http://localhost:5081` и `-ReportPath artifacts/other-results.json`. Проверки используют настоящий HTTP API и SQLite, не изменяют данные. JSON-отчёт по умолчанию записывается в игнорируемый `artifacts/api-smoke-results.json`.

Для браузерных проверок нужен Node.js и установленный Playwright с Chromium. Это инструменты разработки, они не нужны frontend при запуске. Если Playwright находится вне стандартного пути модулей, задайте `PLAYWRIGHT_MODULE_PATH` — абсолютный путь к пакету. Для установленного Chrome/Edge задайте `BROWSER_EXECUTABLE` — путь к браузеру; иначе используется Chromium Playwright.

```powershell
node scripts/test-ui.mjs
```

Опциональная переменная `ECOHELPER_BASE_URL` меняет адрес приложения. Скрипт проходит страницы и формы в настоящем браузере; ошибки HTTP/сети моделируются перехватом запросов только в тестовом браузере. Отчёт и скриншоты сохраняются в `artifacts/ui`. Приложение должно быть запущено отдельно.

Для чата с уже настроенным ключом:

```powershell
node scripts/test-chat.mjs
```

Этот скрипт отправляет четыре контрольных вопроса через API и ещё четыре через настоящий интерфейс Chrome/Chromium. Проверяет переходы с параметрами, ожидание, ошибку/повтор, безопасность вывода и отсутствие постоянной истории. Отчёт и скриншоты — в `artifacts/chat`. Настройки Playwright такие же, как для `test-ui.mjs`.

Автономные проверки без ключа, сети и изменения рабочей базы:

```powershell
dotnet run --project tests/EcoHelper.Checks/EcoHelper.Checks.csproj
```

Проверки используют подставные ответы Gemini и отдельную SQLite в памяти. Схема ответа, секрет в HTTP-заголовке, таймаут, квота, недоступная модель и другие ошибки проверяются без расходования API-квоты. Это проверки интеграционного кода, а не доказательство качества классификации LLM.

## Поведение интерфейса

Категории, инструкции подготовки, пункты, готовые типы нарушений, рекомендации и организации загружаются с сервера. Frontend показывает загрузку, отсутствие данных, ошибку и кнопку повтора. Расстояния не выводятся.

Поля и текущий шаг автоматически сохраняются при вводе в `sessionStorage` текущей вкладки. Возврат между шагами, перезагрузка и переход на другую страницу сохраняют черновик. «Искать другой предмет» и «Другая ситуация» очищают соответствующую форму. При недоступном хранилище показывается предупреждение, форма продолжает работать в памяти.

В форме нарушения можно выбрать готовый тип или описать ситуацию. Готовый тип имеет приоритет и не вызывает LLM. Без выбранного типа описание передаётся через `/api/violations/resolve-type` в существующий `ILlmIntentService`. Принимается только поддерживаемый тип нарушения из SQLite; если определить его нельзя, форма показывает сообщение и остаётся на первом шаге. Рекомендации по-прежнему получает существующий API из SQLite.

Распознанный тип и соответствующее ему описание сохраняются в том же черновике `ecohelper.violations.v1`. Возврат и перезагрузка не вызывают повторный анализ неизменённого текста. После редактирования описания ранее распознанный тип не используется; готовый тип, выбранный вручную, сохраняет приоритет.

Нажатие на уже выбранный тип, включая предложенный AI, снимает выбор и очищает прежний результат распознавания. При HTTP 422 форма показывает «Не удалось определить тип нарушения» и предлагает уточнить описание или выбрать готовый тип. Повторное продолжение с тем же неподходящим текстом, в том числе после перезагрузки, не вызывает Gemini. Временные ошибки API сохраняют возможность повтора.

Чат хранит сообщения только в DOM текущей страницы, до перезагрузки. Кнопка перехода обновляет в существующем черновике `sessionStorage` только непустые распознанные предмет/тип нарушения и регион/населённый пункт/район. Остальные значения и описание нарушения сохраняются. Ссылки на разделы берутся из фиксированного списка сервера. Общие экологические вопросы получают краткую подсказку о возможностях сервиса; генерация произвольных фактических советов моделью не используется.

Поиск предмета сначала проверяет точное совпадение со справочником, затем допускает маркировку, модель и ограниченный набор уточнений: «батарейки AA», «телефон Samsung A52», «стеклянная банка 500 мл». Неоднозначные категории и произвольные описания не угадываются.

Обе формы используют обязательный «Регион» и необязательные «Населённый пункт» и «Район». Москва и Санкт-Петербург указываются как регион; населённый пункт можно оставить пустым. Пример для области: «Ленинградская область / Всеволожск / Всеволожский район». Поиск использует первый непустой уровень: регион + населённый пункт + район → регион + населённый пункт → регион + район → регион; отсутствующие уточнения пропускаются. При расширении выводится пояснение, поиск никогда не выходит за пределы региона. Если местных организаций нет, доступны общие рекомендации и справочный ресурс.

В запросах Gemini нормализует все три параметра при извлечении: «в Москве», «из Москвы», «под Москвой» → `region: "Москва", settlement: null`; «в Ленинградской области, во Всеволожске» → `region: "Ленинградская область", settlement: "Всеволожск"`. Неназванный регион не угадывается: «в Казани» → `region: null, settlement: "Казань"`, после чего чат просит указать регион. Backend не содержит падежных правил для конкретных городов. Ручные поля работают без LLM с простой нормализацией регистра, пробелов, префиксов и `ё`/`е`.

Ключи черновиков `ecohelper.recycling.v1` и `ecohelper.violations.v1` сохранены. Старое поле `city` переносится в `region` для Москвы/Санкт-Петербурга, для других городов — в `settlement` без угадывания региона. Прежний произвольный адрес нарушения сохраняется как `legacyLocation` и показывается возле новых полей. Миграция `UnifiedLocation` сохраняет существующие данные базы; удалять SQLite-файл не нужно.

Регрессионные проверки исправлений аудита: `node scripts/test-audit-fixes.mjs`. Они используют Chrome/Chromium и локальный API; ответы Gemini подставляются только в тестовом браузере. Настройки Playwright те же, что у остальных браузерных проверок.

Общая модель местоположения проверяется командой `node scripts/test-location.mjs`: уровни поиска, обязательность региона, черновики, обратная навигация, ошибки и передача параметров. Нормализация с реальным Gemini — `node scripts/test-canonical-city.mjs` (7 запросов API и 2 через браузер, расходуют API-квоту). Актуальные результаты — в `docs/location-verification.md`.

Для изменения схемы разработчиком:

```powershell
dotnet tool restore
dotnet ef migrations add MigrationName
```

Обычному запуску `dotnet-ef` не требуется: миграции применяются самим приложением.


## Использование AI-помощника

AI-модуль использует Gemini (`gemini-3.5-flash-lite`) для определения намерения пользователя и извлечения параметров запроса. Пункты приёма, рекомендации и организации берутся из SQLite — модель не генерирует эти сведения.

### Настройка

В терминале из корневой папки проекта сохраните собственный Gemini API key через ASP.NET Core User Secrets:

```powershell
dotnet user-secrets set "Gemini:ApiKey" "ВАШ_API_KEY"
dotnet run
```

Не добавляйте настоящий ключ в файлы проекта или Git. Без ключа поиск и готовые типы нарушений работают, но AI-помощник и определение типа нарушения по описанию недоступны.

### Использование

Откройте http://localhost:5080/assistant.html и введите запрос. Примеры:

- «Куда сдать батарейки в Москве, район Арбат?»
- «Куда сдать старый телефон в Ленинградской области, во Всеволожске, Всеволожский район?»
- «В Москве постоянно сжигают мусор. Что делать?»
- «Где найти раздел для сообщения об экологическом нарушении?»

Указывайте регион явно. Населённый пункт и район необязательны, но помогают уточнить поиск. Кнопки в ответе позволяют перейти в соответствующую форму с распознанными параметрами.

### Ограничения

- Каждый запрос анализируется отдельно: предыдущие сообщения не учитываются. Уточнённый вопрос нужно отправлять целиком.
- Диалог отображается только до перезагрузки страницы и постоянно не сохраняется.
- Содержательные ответы на общие вопросы вроде «Можно ли выбросить батарейки в мусор?» пока не реализованы.
- Данные демонстрационные: учебные пункты и организации не предназначены для планирования поездок или отправки обращений.
