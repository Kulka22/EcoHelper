# Проверка frontend — 9 октября 2026

Этот отчёт описывает этап переноса frontend до подключения AI. Последующая реализация чата и её проверки описаны в `ai-verification.md`.

## Реализация

Frontend раздаётся существующим ASP.NET Core приложением из `wwwroot`. Используются HTML, CSS и нативные JavaScript-модули; сборщик и frontend-фреймворки отсутствуют. Серверные модели, сервисы, контроллеры и схема SQLite не менялись. Исходники `design-reference` и пример ошибки классификации в `docs/regression-cases.json` сохранены.

Созданы:

- `wwwroot/recycling.html`, `violations.html`, `assistant.html`;
- `wwwroot/js/common.js`, `api.js`, `storage.js`, `recycling.js`, `violations.js`;
- `wwwroot/assets/fonts/fonts.css`, 18 файлов WOFF2, три лицензии и описание источников;
- `scripts/test-ui.mjs` и этот отчёт.

Изменены `wwwroot/index.html`, `wwwroot/css/site.css`, `README.md`.

Сохранены цвета, ширина контента, типографика, шапка, футер, формы, карточки, шаги и состояния прототипа. Навигация работает обычными ссылками между HTML-страницами. Учебные пункты явно обозначены, фиктивные расстояния исключены. AI-чат перенесён визуально, отправка отключена.

## API, используемые интерфейсом

| Endpoint | Назначение |
| --- | --- |
| `GET /api/recycling/categories` | Категории для быстрого выбора |
| `GET /api/recycling/search?item=…&city=…&district=…` | Категория, подготовка и пункты |
| `GET /api/violations/types` | Готовые типы из SQLite |
| `GET /api/violations/recommendations?type=…&location=…` | Рекомендации и организации |

Вызовы LLM и `/api/chat` отсутствуют. Свободное описание нарушения сохраняется локально; требуется выбор готового типа.

## Проверка через браузер

Из-за сбоя запуска встроенного браузера использованы установленный Google Chrome в headless-режиме и Playwright. Проверки выполняют клики, ввод, переходы и перезагрузку реальных страниц. Основные сценарии обращаются к настоящему backend.

`node scripts/test-ui.mjs`: 14 проверок пройдены; необработанных ошибок JavaScript и запросов `/api/chat` нет.

1. Навигация между всеми четырьмя страницами; активный пункт меню, локальные шрифты, отсутствие внешних запросов при загрузке страницы.
2. «Куда сдать»: стеклянная банка, Москва, Дорогомилово; индикатор загрузки, подготовка и найденный пункт из API.
3. Возврат по шагам, перезагрузка, переход на главную и обратно; предмет, город и район сохраняются; новый поиск очищает черновик.
4. Пустая выдача для Казани: понятное сообщение, инструкции подготовки остаются видимыми.
5. Неизвестный предмет: пустая выдача; HTML в пользовательском вводе выводится как текст.
6. Ошибка HTTP 503 поиска: сообщение, повтор с успешным ответом, данные сохранены.
7. Ошибка сети при загрузке категорий: повтор и выбор категории.
8. «Сообщить о нарушении»: описание, выбор «Сжигание мусора», Москва; возврат сохраняет описание, тип и место; рекомендации и две организации приходят из API; перезагрузка результата работает.
9. Без местоположения: общие рекомендации и общий ресурс организации.
10. Описание без выбранного типа: понятная валидация, текст сохранён, LLM не вызывается.
11. Ошибка сети при подборе рекомендаций: сообщение и успешный повтор.
12. Ошибка справочника типов, пустой справочник, повтор: описание не теряется.
13. AI-помощник: макет отображается, ввод и отправка отключены.
14. Все страницы на ширинах 320, 390 и 768 px: документ не переполняется по горизонтали; мобильный результат поиска отображается.

Сетевые ошибки и пустой справочник моделируются через перехват запросов исключительно в браузере теста. Для пустой выдачи пунктов используется настоящий ответ API. Задержка ответа поиска позволяет проверить видимость загрузки. В сервер не добавлялись тестовые переключатели или endpoints.

## Учтённые проблемы прототипа и переноса

- Перерисовка формы могла сбрасывать описание при выборе типа: теперь меняются только кнопки, поля связаны с черновиком и сохраняются при каждом вводе.
- Исходные результаты были демонстрационными константами: категории, инструкции, пункты, типы и рекомендации заменены ответами API.
- Расстояния без координат и расчёта удалены; фиктивный контакт футера заменён подписью учебного проекта.
- Широкая навигация на мобильном экране вынесена в отдельную прокручиваемую строку; карточки и формы адаптируются к ширине.
- CSS `display: grid/flex` мог перекрывать скрытие шагов: добавлено явное правило `[hidden]`.
- Запрос с предыдущего шага мог завершиться после возврата: используются отмена запроса и проверка номера актуального запроса.
- Ошибки HTTP, сети, таймаут и некорректный JSON обрабатываются общим API-модулем с повтором запроса.

Визуальная проверка выполнена по скриншотам desktop и mobile. Шрифты локальные, их лицензии включены. Классификация свободного текста и реальный AI-помощник остаются следующими этапами.
