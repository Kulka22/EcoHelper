# Контракты API

Базовый адрес: `http://localhost:5080`. Ответы — JSON. Ошибки входных данных — HTTP 400, `application/problem+json` с `errors`. Отсутствие совпадений — HTTP 200 с пояснением, а не сбой. В обоих сценариях `isDemoData: true`; координат и расстояний нет.

## Общая модель местоположения

Оба GET сценария принимают одинаковые query-параметры:

| Параметр | Обязательный | Значение |
| --- | --- | --- |
| `region` | Да | Регион, максимум 120 символов |
| `settlement` | Нет | Населённый пункт, максимум 120 символов |
| `district` | Нет | Район, максимум 120 символов |

Пустые или пробельные необязательные поля становятся `null`. Пробельный регион даёт HTTP 400. В ответах местоположение представлено объектом:

```json
{ "region": "Ленинградская область", "settlement": "Всеволожск", "district": "Всеволожский район" }
```

Для Москвы/Санкт-Петербурга достаточно региона и необязательного района, `settlement` можно оставить пустым. Ручной ввод сопоставляется буквально после нормализации регистра, пробелов, `ё`/`е`, префиксов «г./город/регион» и префикса/суффикса «район/р-н». Ни морфологического разбора, ни вызова LLM в ручных полях нет.

Общий алгоритм `LocationMatcher` выбирает **первый непустой уровень**, пропуская уточнения, которых нет в запросе:

1. Регион + населённый пункт + район.
2. Регион + населённый пункт.
3. Регион + район.
4. Регион.

Поиск не выходит за пределы региона и применяется только к пунктам, принимающим найденную категорию, либо организациям выбранного типа нарушения. Поле `match` сообщает результат:

```json
{ "level": "region_settlement_district", "isFallback": false }
```

`level`: `region_settlement_district`, `region_settlement`, `region_district`, `region`, `none`. `isFallback: true` означает расширение относительно самого точного применимого уровня; в `message` содержится пояснение. При `none` значение `isFallback` равно `false`.

Старые query-параметры `city` и текстовый `location` больше не используются. Ответы `location` — структурированные объекты; `matchedCity` удалён. Frontend и Gemini переведены на новый контракт одновременно.

## Категории и поиск пунктов

`GET /api/recycling/categories` → массив `{ id, code, name, aliases }`.

Коды: `glass`, `batteries`, `clothes`, `plastic_caps`, `paper`, `electronics`.

`GET /api/recycling/search?item=батарейки&region=Ленинградская область&settlement=Всеволожск&district=Всеволожский район`

Дополнительно обязателен `item`, максимум 120 символов: название, код или синоним. Приоритет имеет точное совпадение; допускаются уточнения «батарейки AA», «телефон Samsung A52», «стеклянная банка 500 мл». Неоднозначные категории не угадываются.

Ответ:

```json
{
  "item": "батарейки",
  "location": { "region": "Ленинградская область", "settlement": "Всеволожск", "district": "Всеволожский район" },
  "match": { "level": "region_settlement_district", "isFallback": false },
  "category": { "id": 2, "code": "batteries", "name": "Батарейки" },
  "preparationInstructions": ["Инструкция из SQLite"],
  "points": [
    {
      "id": 5,
      "name": "Учебный пункт «Всеволожск»",
      "address": "Демонстрационный адрес, Ленинградская область, Всеволожск",
      "location": { "region": "Ленинградская область", "settlement": "Всеволожск", "district": "Всеволожский" },
      "workingHours": "Демо: ежедневно 10:00–18:00",
      "website": null,
      "acceptedCategories": [{ "id": 2, "code": "batteries", "name": "Батарейки" }]
    }
  ],
  "message": null,
  "isDemoData": true
}
```

Массив `points` содержит `{ id, name, address, location, workingHours, website, acceptedCategories }`. `location` — та же тройка, `acceptedCategories` — массив `{ id, code, name }`. ID не следует фиксировать в клиенте. В примере сокращён список принимаемых категорий; учебные записи Всеволожска присутствуют в SeedData.

При неизвестном предмете `category: null`, инструкции/пункты пусты. Если категория известна, но во всём регионе нет пунктов, инструкции сохраняются, `points` пуст и `match.level: none`.

## Типы нарушений и рекомендации

`GET /api/violations/types` → массив `{ id, code, name }`:

- `illegal_dumping` — незаконная свалка;
- `waste_burning` — сжигание мусора;
- `water_pollution` — загрязнение водоёма;
- `illegal_logging` — незаконная вырубка деревьев.

`GET /api/violations/recommendations?type=waste_burning&region=Ленинградская область&settlement=Всеволожск&district=Всеволожский район`

Дополнительно обязателен `type`, максимум 120 символов: существующий код, ID или название типа. Неизвестный тип даёт HTTP 400. GET никогда не вызывает Gemini.

Ответ: `{ type, location, match, isGeneralAdvice, recommendations, whatToRecord, organizations, message, isDemoData }`. Тип — объект справочника. Местоположение и результат поиска — общая модель выше.

Организация: `{ id, name, location, website, description }`. `location: null` означает общий справочный ресурс, который добавляется к выбранным местным организациям. Если подходящих местных организаций во всём регионе нет, `isGeneralAdvice: true`, `match.level: none`, остаются рекомендации и общий ресурс из SQLite. Приложение не отправляет обращения.

## Определение типа по описанию

`POST /api/violations/resolve-type`, `Content-Type: application/json`:

```json
{ "description": "Во дворе постоянно сжигают мусор. Что делать?" }
```

Необязательный `type` — существующий код, максимум 120 символов; `description` — максимум 1500. Нужно непустое значение хотя бы одного поля. Размер тела — максимум 16 KiB.

Если тип указан, он проверяется по SQLite без Gemini, даже при противоречащем описании. Неизвестный явный тип — HTTP 400 без классификации. Иначе общий `ILlmIntentService` определяет тип; принимается только `environmental_violation` с кодом справочника. HTTP 200 возвращает `{ id, code, name }`, после чего frontend запрашивает рекомендации с тремя полями местоположения.

Если определить тип нельзя: HTTP 422, ProblemDetails с `code: violation_type_unknown`. Frontend показывает «Не удалось определить тип нарушения» и предлагает уточнить описание или выбрать готовый тип. Неизменённый неподходящий текст повторно не отправляется; временные ошибки сохраняют кнопку повтора. Рекомендации модель не генерирует.

## AI-помощник

`POST /api/chat`, `Content-Type: application/json`:

```json
{ "message": "Куда сдать батарейки в Ленинградской области, во Всеволожске?" }
```

`message` обязателен, максимум 2000 символов. Пустой/пробельный текст и некорректный JSON — HTTP 400; тело больше 16 KiB — HTTP 413; GET — HTTP 405 без Gemini.

Gemini возвращает ровно семь обязательных ключей, все кроме `intent` могут быть `null`:

```json
{
  "intent": "find_disposal",
  "item": "Батарейки",
  "region": "Ленинградская область",
  "settlement": "Всеволожск",
  "district": null,
  "violationType": null,
  "section": null
}
```

Модель нормализует названия при извлечении, включая падежи. «В Москве», «из Москвы», «под Москвой» → `region: Москва`, `settlement: null`. Для «в Казани» неназванный регион не угадывается: `region: null`, `settlement: Казань`. Река Москва не трактуется как регион Москва. Backend не содержит специальных правил склонения.

Готовый ответ backend: `{ intent, message, actions, recycling, violation }`. Последние два поля — полный ответ соответствующего сервиса либо `null`. Действие: `{ label, url, parameters }`; `parameters` содержит `item`, `region`, `settlement`, `district`, `violationType`, допускающие `null`.

| intent | Действие backend |
| --- | --- |
| `find_disposal` | RecyclingService при известных предмете и регионе; иначе запрос уточнения и переход |
| `environmental_violation` | ViolationService при известных типе и регионе; иначе выбор типа/региона |
| `navigation` | Фиксированное преобразование кода раздела в URL |
| `ecology_help` | Подсказка о возможностях сервиса без вымышленных фактов |
| `unknown` | «Я могу помочь только с вопросами об экологии и возможностях Экопомощника.» без действий |

Допустимы только `/`, `/recycling.html`, `/violations.html`, `/assistant.html`; модель возвращает код раздела, не URL. При переходе только непустые распознанные параметры обновляют существующий черновик `sessionStorage`. Описание нарушения сохраняется. Постоянной истории чата нет.

Gemini `gemini-3.5-flash-lite` вызывается только сервером с structured JSON output (`responseMimeType` и `responseJsonSchema`). Проверяются ключи, типы, enum, длины, дубли и лишние поля. Модель получает только текст и названия/коды справочников. Пункты, рекомендации и организации сервер получает из SQLite.

Ключ читается из `Gemini:ApiKey` в User Secrets, передаётся заголовком `x-goog-api-key`, не попадает в URL/frontend. Запросы/ответы Gemini и ключ не логируются приложением.

| HTTP | code | Ситуация |
| --- | --- | --- |
| 429 | `quota` | Квота Gemini |
| 502 | `invalid_output` | Некорректный structured output |
| 502 | `provider_http_*` | Другой отказ провайдера |
| 503 | `not_configured`, `credentials`, `model_unavailable`, `unsupported_location` | Настройка/доступ/модель/регион |
| 503 | `connection`, `provider_unavailable` | Сеть/временная недоступность |
| 504 | `timeout` | Таймаут анализа |

Срок обращения к Gemini — 22 секунды, frontend ждёт до 30. Для 429/5xx допускается один короткий повтор, долгий Retry-After не блокирует запрос. 400/403/404 автоматически не повторяются; фиктивного intent при сбое нет.
