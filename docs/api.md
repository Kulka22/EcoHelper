# Контракты API: этапы 1–4

Базовый адрес: `http://localhost:5080`. Все endpoints ниже используют GET и возвращают JSON. Обязательные параметры проверяются на пустые и пробельные значения. Ошибки валидации возвращают HTTP 400 и `application/problem+json` с полем `errors`.

В успешных ответах двух сценариев `isDemoData` равно `true`. Нулевое количество совпадений — успешный HTTP 200 с пустым массивом и пояснением в `message`, а не ошибка сервера. Необработанные ошибки обслуживаются стандартным ProblemDetails без раскрытия внутренних деталей.

## Категории

`GET /api/recycling/categories`

Возвращает массив `{ id, code, name, aliases }`. Доступные коды: `glass`, `batteries`, `clothes`, `plastic_caps`, `paper`, `electronics`.

## Поиск пунктов

`GET /api/recycling/search?item=батарейки&city=Москва&district=Арбат`

| Параметр | Обязательный | Ограничение |
| --- | --- | --- |
| `item` | Да | 120 символов; название, код или синоним из справочника |
| `city` | Да | 120 символов |
| `district` | Нет | 120 символов; пустое значение означает весь город |

Сопоставление учитывает регистр кириллицы, лишние пробелы и `ё`/`е`. Для города допускаются префиксы `г.`, `г` и `город`; для района — префикс/суффикс `район` или `р-н`. Полнотекстовое понимание предложений здесь не применяется.

Ответ:

```json
{
  "item": "батарейки",
  "city": "Москва",
  "district": "Арбат",
  "category": { "id": 2, "code": "batteries", "name": "Батарейки" },
  "preparationInstructions": ["Инструкция из БД"],
  "points": [
    {
      "id": 2,
      "name": "Учебный пункт «Батарейки и техника»",
      "address": "Демонстрационный адрес №2, район Арбат",
      "city": "Москва",
      "district": "Арбат",
      "workingHours": "Демо: пн–сб 11:00–20:00",
      "website": null,
      "acceptedCategories": [
        { "id": 2, "code": "batteries", "name": "Батарейки" },
        { "id": 6, "code": "electronics", "name": "Электроника" }
      ]
    }
  ],
  "message": null,
  "isDemoData": true
}
```

Числовые ID в примере иллюстративны; клиент получает их из API и не должен жёстко фиксировать. Расстояния и координаты отсутствуют в контракте.

При неизвестном предмете `category` равна `null`, массивы инструкций и пунктов пусты. При известной категории, но неподходящем городе или районе инструкции сохраняются, `points` пуст. Район применяется как точный фильтр после нормализации; автоматического расширения поиска нет.

## Типы нарушений

`GET /api/violations/types`

Возвращает массив `{ id, code, name }`:

- `illegal_dumping` — незаконная свалка;
- `waste_burning` — сжигание мусора;
- `water_pollution` — загрязнение водоёма;
- `illegal_logging` — незаконная вырубка деревьев.

## Рекомендации

`GET /api/violations/recommendations?type=waste_burning&location=Москва, район Арбат`

| Параметр | Обязательный | Ограничение |
| --- | --- | --- |
| `type` | Да | 120 символов; существующий код, ID либо название типа |
| `location` | Нет | 300 символов; адрес или описание местоположения |

Ответ содержит `type`, исходное `location`, `matchedCity`, `isGeneralAdvice`, массивы `recommendations`, `whatToRecord`, `organizations`, а также `message` и `isDemoData`.

Каждая организация: `{ id, name, city, website, description }`. `city: null` обозначает общий справочный ресурс. `website` — ссылка для получения сведений об обращении; приложение не отправляет его.

При явно указанной Москве возвращается московская организация и общий ресурс. Местоположение сопоставляется с городами организаций из БД по границам слов, без геокодирования и без LLM. Сейчас в демонстрационной базе местные организации есть только для Москвы. Если местоположение отсутствует, неоднозначно или город не распознан, возвращаются общие рекомендации и общий ресурс, `matchedCity: null`, `isGeneralAdvice: true`. Названия организаций не составляются из введённого пользователем адреса.

Неизвестный тип возвращает HTTP 400 с предложением выбрать значение из `/api/violations/types`. Свободное описание непосредственно в форме нарушения пока не интерпретируется как тип. Выбор готового типа не вызывает LLM.

## AI-помощник

`POST /api/chat`, `Content-Type: application/json`

```json
{ "message": "Куда сдать батарейки?" }
```

`message` обязателен, не может состоять из пробелов, максимум 2000 символов. Размер тела ограничен 16 KiB. Отсутствующий/пустой/слишком длинный текст и некорректный JSON дают HTTP 400, превышение размера — HTTP 413. GET возвращает 405 и не вызывает Gemini.

Успешный ответ HTTP 200:

```json
{
  "intent": "find_disposal",
  "message": "Укажите город в разделе «Куда сдать», чтобы найти пункты в базе.",
  "actions": [
    {
      "label": "Куда сдать",
      "url": "/recycling.html",
      "parameters": {
        "item": "Батарейки", "city": null, "district": null,
        "violationType": null, "location": null
      }
    }
  ],
  "recycling": null,
  "violation": null
}
```

В примере город не указан, поэтому `recycling` равен `null`, а сообщение просит указать город. При найденных item/city это поле содержит полный `RecyclingSearchResponse`, описанный выше. Неизвестный предмет или отсутствие пунктов возвращаются как корректный HTTP 200 с пустыми результатами сервиса поиска.

| intent | Действие backend |
| --- | --- |
| `find_disposal` | `RecyclingService`, если известны предмет и город; иначе подсказка и переход |
| `environmental_violation` | `ViolationService` для существующего кода типа; результат в `violation`; иначе выбор типа |
| `navigation` | Код раздела преобразуется в заранее заданный URL |
| `ecology_help` | Подсказка о возможностях Экопомощника и кнопки двух сценариев, без выдуманных фактов |
| `unknown` | `Я могу помочь только с вопросами об экологии и возможностях Экопомощника.`; действия отсутствуют |

`actions[].url` — только `/`, `/recycling.html`, `/violations.html`, `/assistant.html`. Gemini возвращает код раздела (`home`, `recycling`, `violations`, `assistant`), а не URL. `parameters` предназначены для существующих черновиков форм; чат не сохраняется в `sessionStorage`.

Gemini `gemini-3.5-flash-lite` (согласованная замена недоступной 2.5) вызывается только backend, с `responseMimeType: application/json` и `responseJsonSchema`. Модель получает текст пользователя и названия/синонимы категорий, коды/названия типов из SQLite. Адреса, рекомендации и организации ей не передаются для генерации ответа. После получения результата сервер проверяет семь обязательных полей, типы, enum, длины, повторы ключей и лишние поля. Обычный текст, markdown и произвольные URL не принимаются.

Ключ читается из `Gemini:ApiKey`, отправляется в `x-goog-api-key`, отсутствует в URL. Содержимое запросов и ответов Gemini не логируется приложением; HTTP-логирование этого клиента отключено. Постоянной истории нет, каждый запрос анализируется независимо.

Ошибки в формате ProblemDetails с безопасными `detail` и `code`:

| HTTP | code | Ситуация |
| --- | --- | --- |
| 429 | `quota` | Ограничение Gemini; клиенту предлагается подождать и повторить |
| 502 | `invalid_output` | Некорректный/неполный structured output |
| 502 | `provider_http_*` | Другой отказ провайдера |
| 503 | `not_configured`, `credentials`, `model_unavailable`, `unsupported_location` | Ключ/доступ/модель/регион |
| 503 | `connection`, `provider_unavailable` | Сеть или временная недоступность провайдера |
| 504 | `timeout` | Превышен таймаут анализа |

Общий срок обращения к Gemini — 22 секунды, frontend ожидает до 30 секунд. Для 429/5xx допускается один повтор с задержкой; долгий Retry-After не блокирует запрос. Ошибки 400/403/404 не повторяются автоматически. При сбое реальный результат не подменяется фиктивным intent.
