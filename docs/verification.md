# Проверка этапов 1–4

Дата: 9 октября 2026 года. Проверено на Windows с .NET SDK 9.0.306. Локальный адрес приложения: `http://localhost:5080`.

## Результаты

- `dotnet restore EcoHelper.csproj` — успешно.
- `dotnet tool restore` — восстановлен локальный `dotnet-ef` 9.0.16.
- `dotnet build EcoHelper.csproj --no-restore` — 0 ошибок, 0 предупреждений, включая сборку после создания миграции.
- `dotnet ef migrations has-pending-model-changes --no-build` — модель соответствует миграции, незаписанных изменений схемы нет.
- Перед первым запуском `App_Data/ecohelper.db` отсутствовал. `dotnet run --no-build --no-restore` применил `20261009181424_InitialCreate`, создал SQLite и заполнил базу.
- `scripts/Test-Api.ps1` — 19 из 19 групп проверок прошли на настоящем HTTP API.
- После остановки и повторного запуска приложение сообщило, что база актуальна. Все 19 групп проверок снова прошли.
- Полные ответы справочников, поиска по всем 6 категориям и рекомендаций по всем 4 типам с местоположением Москва совпали до и после перезапуска. Сохранились те же ID, данные и количества: 6 категорий, 3 уникальных пункта, 4 типа нарушения и 8 записей связи организаций с типами. Повторного заполнения нет.
- Дополнительно `POST /api/chat` вернул HTTP 404: AI endpoint на этом этапе отсутствует.

## Проверенное поведение

1. Главная страница и CSS раздаются из `wwwroot`.
2. Категории и их синонимы возвращаются из SQLite.
3. Все 6 категорий находят подходящие учебные пункты, и каждый пункт принимает искомую категорию.
4. Регистр кириллицы, пробелы, `ё`/`е` и префиксы города/района нормализуются.
5. Батарейки не получают пункты и инструкции для стекла.
6. Неизвестный предмет возвращает HTTP 200 с пустой выдачей и пояснением.
7. Неизвестный город возвращает пустую выдачу, сохраняя инструкции по подготовке.
8. Район действительно фильтрует пункты; пустой район означает весь город.
9. Отсутствующие, пробельные и слишком длинные обязательные параметры дают HTTP 400 и ProblemDetails.
10. Строка, похожая на SQL, обрабатывается как обычный неизвестный предмет.
11. Все 4 готовых типа нарушений работают через БД без LLM.
12. Без местоположения выдаются общие рекомендации и справочный ресурс.
13. Для явно указанной Москвы добавляется московская организация со ссылкой.
14. Неизвестное или неполное местоположение не порождает вымышленную местную службу.
15. Тип нарушения принимается по коду, существующему ID или нормализованному названию.
16. Свободное описание не имитирует распознавание: пока нужно выбрать готовый тип.
17. В контрактах нет фиктивных расстояний.
18. SQLite, `appsettings.json` и материалы Figma недоступны через статическую раздачу.
19. Пример неправильной классификации фразы про сжигание мусора сохранён для последующей проверки AI и отчёта.

Воспроизводимый скрипт: `scripts/Test-Api.ps1`. Машинные отчёты и снимки до/после перезапуска находятся в игнорируемом `artifacts/`; они не требуются для запуска приложения.

## Отложено по границам текущего этапа

Полный интерфейс Figma, пошаговые формы с сохранением в `sessionStorage`, общий LLM-сервис, свободное описание нарушения и AI-чат. Никаких реальных обращений приложение не отправляет. Учебные пункты явно обозначены как демонстрационные, их адреса и часы не являются сведениями о реальных местах приёма.
