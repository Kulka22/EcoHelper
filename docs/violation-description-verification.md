# Свободное описание нарушения: исправление и проверка

9 октября 2026. Приложение: `http://localhost:5080/violations.html`.

## Причина

`wwwroot/js/violations.js` требовал готовый тип для перехода с первого шага. `description` сохранялся в sessionStorage, но не отправлялся на сервер. GET рекомендаций требовал `type`, а общий Gemini-сервис использовался только чатом. Это было ограничение предыдущего этапа, а не ошибка Gemini.

## Минимальное изменение

В существующий `ViolationsController` добавлен POST `resolve-type`, в `ViolationDtos.cs` — DTO его запроса. Endpoint использует существующие `ViolationService` и `ILlmIntentService`, текущую согласованную модель `gemini-3.5-flash-lite` и прежний ключ User Secrets. Новые сервисы, схема SQLite, миграции и изменения Gemini-клиента не потребовались.

- Готовый код типа имеет приоритет; LLM не вызывается. Неизвестный явный код отклоняется без LLM.
- Без кода непустое описание анализируется Gemini. Принимается только intent `environmental_violation` и существующий код из SQLite.
- Неопределённый тип даёт HTTP 422 с понятным сообщением; рекомендации не придумываются.
- После определения типа прежний GET рекомендаций получает фактические данные из SQLite, без нового вызова LLM.

В форме изменены обработчик первого шага и поясняющий текст, сохранены дизайн и шаги. Загрузка, ошибка и повтор используют существующие компоненты. Ключ черновика `ecohelper.violations.v1` сохранён; добавлены `resolvedTypeCode` и `resolvedDescription`, старые черновики совместимы. Неизменённое описание использует сохранённый результат после возврата/перезагрузки. Изменённый текст не использует старую классификацию. Явный выбор сохраняет приоритет над описанием. Выбор готового типа во время анализа отменяет запрос и защищён от позднего ответа.

## Реальные проверки Gemini

| Описание | Результат |
| --- | --- |
| Во дворе постоянно сжигают мусор. Что делать? | HTTP 200, `waste_burning` |
| Возле дома появилась большая незаконная свалка отходов. Что делать? | HTTP 200, `illegal_dumping` |
| Как дела? | HTTP 422, `violation_type_unknown`, без рекомендаций |

Через настоящий интерфейс Chrome пройден сценарий с первым описанием: определение типа, ввод Москвы, возврат, перезагрузка, получение рекомендаций и организаций из SQLite. На неизменённый текст выполнен ровно один запрос классификации.

## Остальные проверки

- Сборка: 0 ошибок и предупреждений.
- 54 автономные проверки; 15 новых проверок контроллера. Счётчик подставного LLM и исключение при его вызове доказывают обход LLM для всех четырёх готовых типов, включая противоречащее описание. Проверены пустой ввод, неизвестный явный код, все четыре распознанных типа, неподходящий intent, отсутствующий/придуманный код и ошибка провайдера. Данные проверяются на SQLite в памяти.
- `scripts/test-violation-description.mjs`: три реальных API-запроса выше, четыре проверки HTTP-валидации и приоритета всех четырёх готовых типов; шесть браузерных сценариев. Один сценарий интерфейса вызывает настоящий Gemini; остальные используют контролируемые ответы для отказа, повтора, изменения текста, сохранения черновика и отмены устаревшего запроса.
- Прежние 14 проверок frontend и 19 проверок API сохранены; старый тест, запрещавший описание без выбора, заменён проверкой пустого первого шага.

Отчёт и скриншоты нового сценария: `artifacts/violation-description/`. Регрессионный отчёт: `artifacts/violation-api-regression.json`. Артефакты исключены из Git.

При отладке новых тестов исправлены две ошибки самих проверок: предположение о статусе ProblemDetails при прямом вызове контроллера без MVC-фабрики и увеличение счётчика запроса внутри `Array.find`. Проверки валидации HTTP отдельно подтверждают реальные статусы сервера. Функциональное исправление не потребовало изменения архитектуры или дизайна.
