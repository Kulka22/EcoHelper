# AI-помощник: реализация и проверка

Дата: 9 октября 2026. Приложение: `http://localhost:5080`.

## Реализация

Добавлены `Services/ILlmIntentService.cs`, `GeminiIntentService.cs`, `ChatService.cs`, `DTO/ChatDtos.cs`, `Controllers/ChatController.cs`, `wwwroot/js/assistant.js`. В `Program.cs` зарегистрированы сервисы и HTTP-клиент. Серверные модели, SQLite, миграции, `RecyclingService` и `ViolationService` не менялись.

Gemini возвращает только intent и параметры по JSON-схеме из семи полей. Backend строго проверяет JSON и самостоятельно выбирает сервис/страницу. Названия, адреса, часы, подготовка, рекомендации и организации приходят из SQLite. Модель не генерирует текст фактического ответа. `ecology_help` даёт подготовленную сервером подсказку о поддерживаемых сценариях; полноценной генерации экологических объяснений нет.

Системная инструкция ограничивает классификацию экологией и возможностями Экопомощника, явно исключает политику, развлечения, программирование и постороннее общение. Пример про сжигание мусора включён как приоритетный пример нарушения; исходный regression case сохранён.

Обновлены `assistant.html`, общий API-модуль, модуль черновиков, сценарные JS, CSS и текст FAQ главной. Чат отправляет POST, показывает ожидание, ответ, ошибку и повтор. Повтор не дублирует сообщение пользователя. Кнопки передают параметры в существующие ключи `ecohelper.recycling.v1`/`ecohelper.violations.v1`. Если город отсутствует, Москва не подставляется. История живёт только в DOM страницы; после перезагрузки диалог пустой.

`Gemini:ApiKey` читается из ASP.NET Core конфигурации/User Secrets. Его значение не переносилось в проект, браузер, отчёты или команды. Ключ передаётся в HTTP-заголовке, не в URL. HTTP-логи Gemini-клиента отключены; сервер пишет только безопасный код ошибки, без ключа, сообщения пользователя и полного ответа провайдера.

## Четыре обязательных реальных запроса

Каждый запрос успешно проверен отдельно через `/api/chat` и через интерфейс Chrome (ввод, нажатие «Отправить», отображение и переход). Все ответы HTTP 200.

| Запрос | Intent | Результат |
| --- | --- | --- |
| Куда сдать батарейки в Москве? | `find_disposal` | Предмет «Батарейки», город «Москва»; категория batteries, один учебный пункт, подготовка из SQLite; переход в форму с предметом и городом |
| Во дворе постоянно сжигают мусор. Что делать? | `environmental_violation` | Тип waste_burning, общие рекомендации и справочный ресурс; переход к нарушению с выбранным типом; слово «мусор» не переключает в поиск сдачи |
| Где найти раздел для сообщения об экологическом нарушении? | `navigation` | Серверная кнопка `/violations.html`, без произвольного URL модели |
| Как дела? | `unknown` | Точное сообщение «Я могу помочь только с вопросами об экологии и возможностях Экопомощника.»; без действий |

Фраза «во дворе» может извлекаться как относительное местоположение. Город при этом не придумывается: `matchedCity: null`, `isGeneralAdvice: true`. Этот ориентир сохраняется при переходе в форму, если он распознан.

## Возникшие проблемы и исправления

1. **Запрошенная модель 2.5 недоступна.** Первый реальный запрос к `gemini-2.5-flash-lite` получил upstream HTTP 404 с признаком «no longer available to new users». Общая ошибка сначала скрывала конкретную причину. Добавлен безопасный разбор известных ошибок модели/ключа/региона. После явного согласия пользователя модель заменена на `gemini-3.5-flash-lite`. С ней реальные запросы успешны. Автоматической смены модели или фиктивного fallback нет.
2. **Проверка гипотезы о VPN/РФ.** Пользователь подтвердил отдельное включённое VPN-приложение. Windows-прокси, PAC и proxy-переменные не настроены, что допустимо для системного VPN-туннеля. Фактический отказ относился к доступу новых проектов к модели, а не к региону. Сетевые настройки и VPN не менялись; после замены модели доступ работает в текущей конфигурации.
3. **Относительное место в regression case.** Первая версия теста чрезмерно требовала `location: null`; Gemini вернула «во дворе», сохранив правильные intent и тип. Исправлена проверка: допускает null или этот исходный ориентир, обязательно требует отсутствия выдуманного города и общих рекомендаций. Значение не удаляется из распознанных параметров.
4. **Устаревшие тесты предыдущего этапа.** Проверка отсутствия `/api/chat` и отключённого ввода закономерно перестала проходить. Заменена проверками POST-only endpoint и готового интерфейса без вызова AI до отправки сообщения.
5. **Перенос номеров инструкций в узкой карточке.** Визуальная проверка выявила разрыв «02»/«03» на строки из-за сжатия flex-элемента. Ширина номера закреплена, перенос отключён; desktop/mobile проверены повторно.

Для надёжности добавлены backend-дедлайн 22 секунды и ожидание frontend 30 секунд, один ограниченный повтор для временных ошибок, отмена при отключении клиента, контроль ответа и фиксированный список страниц. Эти защитные сценарии проверены автономно; реальные ошибки квоты/таймаута/ключа специально не вызывались.

Использованы официальные описания [structured output](https://ai.google.dev/gemini-api/docs/structured-output), [GenerateContent API](https://ai.google.dev/api/generate-content) и [ошибок/повторов](https://ai.google.dev/gemini-api/docs/troubleshooting).

## Ограничения текущего этапа

Свободное описание непосредственно в форме «Сообщить о нарушении» ещё не вызывает Gemini. Готовый тип использует SQLite. Диалог не учитывает предыдущие сообщения на backend: каждый вопрос анализируется самостоятельно. Данные пунктов учебные; координаты, расстояния и отправка обращений отсутствуют. Запуск `test-chat.mjs` расходует квоту Gemini.
