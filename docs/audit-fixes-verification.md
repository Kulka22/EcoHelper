# Исправления выбранных пунктов аудита

Дата проверки: 10 октября 2026 года. Исправлены №1, №2, №3, №6 и №10. Остальные пункты аудита не включены в этот этап.

Уточнение последующего этапа: описанная ниже серверная обработка падежей №1 заменена нормализацией в Gemini по запросу пользователя. Текущее поведение и результаты проверок описаны в `canonical-city-verification.md`; этот документ сохраняет результаты первоначального исправления.

## Изменения и проверки

| Пункт | Изменение | Проверка |
| --- | --- | --- |
| №1 | При выборе местной организации учитываются падежные формы Москвы. Упоминание Москвы-реки исключается из определения города. | SQLite в памяти и реальный HTTP API: «в Москве», «из Москвы», «через Москву», «под Москвой», «г. Москва» возвращают московскую организацию. «Москва-река, город Коломна» и «Московская область, река Москва» возвращают только общий ресурс. В Chrome пройден полный сценарий с местом «в Москве, район Арбат». |
| №2 | Переключение кнопки сравнивается с фактически выбранным типом, включая результат AI. Снятие выбора очищает ручной тип и прежнее распознавание. | В Chrome подставлено распознавание сжигания, затем выбранный тип снят одним кликом. После смены описания на загрязнение воды получен новый тип. Выбор другого готового типа не вызывает LLM. |
| №3 | Переход из чата обновляет только непустые параметры нужного сценария. Описание нарушения сохраняется. При передаче только местоположения сохраняется ранее распознанный тип. | В Chrome проверены сохранение города/района при смене предмета, сохранение описания/адреса при смене типа, передача только местоположения и новый поиск без явно указанного города. Новый черновик не получает Москву автоматически. Ключи sessionStorage прежние. |
| №6 | HTTP 422 показывает «Не удалось определить тип нарушения» и предложение уточнить описание или выбрать готовый тип. Кнопки повтора ошибки загрузки нет. Последнее неподходящее описание сохраняется в том же черновике. | В Chrome повторные нажатия «Продолжить» и перезагрузка с тем же текстом не отправляют новый запрос. Изменение текста разрешает распознавание; ручной выбор работает без LLM. Для HTTP 503 сохранён обычный повтор. Реальный Gemini вернул 422 для «Как дела?». |
| №10 | После точного совпадения допускается известный синоним отдельными словами с маркировкой/моделью и ограниченными уточнениями. Несколько категорий в запросе остаются неоднозначными. | «батарейки AA», «Батарейки (AAA) 1,5V», «Duracell батарейки АА», «телефон Samsung A52», «стеклянная банка 500 мл» получают категорию, инструкции и пункты из SQLite. «небатарейки AA», «коробка от батарейки», «батарейки и одежда», «glass batteries» не получают случайную категорию. Через Chrome пройден полный поиск «батарейки AA». |

Сопоставление города ограничено текущим справочником: падежные формы предусмотрены для Москвы, единственного города местных организаций в демонстрационной базе. Для новых городов пока используется точное название из БД. Поиск предмета не заменяет анализ произвольного текста.

## Результаты запусков

- `dotnet build --no-restore`: успешно, 0 ошибок, 0 предупреждений.
- `dotnet run --project tests/EcoHelper.Checks/EcoHelper.Checks.csproj --no-restore`: 82 проверки, включая 28 новых случаев сопоставления города и предмета. SQLite в памяти, без реального Gemini.
- `powershell -ExecutionPolicy Bypass -File scripts/Test-Api.ps1`: 19 проверок реального локального API прошли.
- `node scripts/test-ui.mjs`: 14 существующих браузерных проверок прошли, необработанных ошибок JavaScript нет.
- `node scripts/test-audit-fixes.mjs`: 11 новых регрессионных проверок прошли. Локальный API настоящий; ответы Gemini для управления состояниями подставлены только в тестовом браузере.
- `node scripts/test-violation-description.mjs`: 3 реальных запроса Gemini, 4 проверки валидации, 4 готовых типа и 6 браузерных проверок прошли. Реальное распознавание в форме проверено на фразе «Во дворе постоянно сжигают мусор. Что делать?».

Результаты реального Gemini: сжигание → `waste_burning`, свалка → `illegal_dumping`, «Как дела?» → HTTP 422 / `violation_type_unknown`. Дополнительных проблем интеграции Gemini в этом прогоне не возникло.

Приложение запущено на `http://localhost:5080`. Схема SQLite, контроллеры, модель Gemini и хранение ключа не изменялись в рамках этих исправлений. Рекомендации и организации по-прежнему поступают только из SQLite.
